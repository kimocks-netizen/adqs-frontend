## Architecture Decisions

### Data flow:
  Dummy data (src/data/) → page components (Phases 1–13)
  Real server data → TanStack Query (features/*/queries.ts) wired in Phase 14
  Client state (auth) → Zustand (stores/useAuthStore.ts)

### API communication:
  lib/api-client.ts → Express backend (VITE_API_URL)
  Features call api-client via features/*/api.ts
  Pages consume data via features/*/queries.ts hooks
  Direct dummy data imports until Phase 14

### Forms:
  React Hook Form + Zod schemas
  Used for: contact form, admin login, article editor
  shadcn/ui Form components for consistent field rendering

### Auth:
  JWT token stored in localStorage (key: adqs_token)
  Zustand useAuthStore — hydrate() called on app mount
  ProtectedRoute wraps all /admin/* pages
  ApiClient auto-injects Bearer token on all requests
  401 response → clearToken() → redirect to /admin/login

### Layout:
  PublicLayout — Navbar + <Outlet> + Footer (all public pages)
  AdminLayout — sidebar + header + <Outlet> (all /admin/* pages)
  AdminLoginPage — standalone, no layout wrapper

### Styling:
  Tailwind v4 with @theme inline CSS variables
  No dark mode — ADQS is light-only (professional legal brand)
  Brand tokens: --color-primary (navy), --color-secondary (gold)
  Utility classes: bg-brand-gradient, bg-gold-gradient, text-brand-gradient
  Shadow utilities: shadow-glow, shadow-gold, shadow-card
  motion (framer-motion) for scroll-reveal and entrance animations

### Feature module pattern:
  features/<domain>/api.ts — typed fetch functions
  features/<domain>/queries.ts — TanStack useQuery hooks
  features/<domain>/mutations.ts — TanStack useMutation hooks
  Pages import from features/ — never call lib/api-client.ts directly
  All features are stubs until Phase 14 (backend wiring)
